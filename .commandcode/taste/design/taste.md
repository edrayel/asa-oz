# Taste

- Wants consistent layout, alignment, and content width across all pages — subpages should replicate the homepage's sections and match its visual rhythm and constrained content width rather than diverging (e.g., about.html/faq.html were "heavily left-aligned" compared to index.html; later flagged again for content spreading too wide on the left/right instead of matching index's width). Confidence: 0.9

- Prefers slick, minimalist UI treatments (e.g., founder photo refactored into "a carousel that is slick and minimalist") while preserving the existing styling of established components. Confidence: 0.7

- Prefers calm, slower motion for animated/immersive features (e.g., reduce the wall-of-moments default scrolling speed) and seamless, infinite/continuous experiences over finite or jumpy ones. Confidence: 0.7

- Prefers conservative defaults for in-flux features: content/sections that aren't final should be off/hidden by default and only appear when explicitly enabled (e.g., "Make it off/hidden by default for now" for the membership pricing section — hidden unless toggled on in admin), rather than shown until disabled. Repeated for membership section, About YouTube embed, and prices hiding. Confidence: 0.8

- Treats the existing "premium" look as the design system to extend: design changes/refactors (e.g., making the header sticky) must be "beautiful and consistent with the existing premium design and look currently used" rather than introducing a new visual style. Confidence: 0.75

- Cares about pixel-level responsive polish — spacing (e.g., header padding) should be "perfectly balanced across different screen sizes," not tuned to a single breakpoint; expects responsive spacing scales that hold at every width. Confidence: 0.7

- Expects optical centering of text inside UI elements (buttons/pills), not just CSS box centering — e.g., noticed a short uppercase button label sitting "not perfectly center-aligned" and expected it debugged and fixed even though the offset was ~1px (font asc/descent imbalance under `line-height: 1`, plus trailing letter-spacing bias). Treats sub-pixel/optical misalignment as a real defect to fix. Confidence: 0.6

- Expects UI/visual changes to be verified by actually viewing rendered screenshots (vision-enabled image inspection), not just by measuring DOM values/numeric CSS — will point out that vision is available so the agent looks at the captured images rather than only reading back computed styles. Confidence: 0.55

- Rejects generic/templated layout patterns and expects something more creative and bespoke — explicitly rules out a "basic column split" and wants the arrangement to feel intentional and responsive across all screen sizes (e.g., composing two text blocks around a portrait film as an asymmetric "staircase" rather than a side-by-side columns layout). Confidence: 0.7

- When adding new media/features to a page, wants an additive treatment that retains the existing content rather than a swap/replacement — explicitly "I don't want a swap replacement. I want both the existing text to be retained while the video is available." New elements should complement, not displace, what's already there. Reiterated when a new blog-teaser section replaced the existing wall-of-moments gallery marquee: the user flagged the wiped section as broken and demanded it be restored, so swapping out a shipped section to make room for a new one is treated as destroying intended design. Confidence: 0.75

- Expects related visual components/surfaces to join a single shared "recipe" rather than each hardcoding its own variant — notices when two similar panels diverge (e.g. a `.film-band` not matching the `.proof-glass` treatment across width, radius, border, background, backdrop-filter, shadow) and asks "Is that intentional?", treating unintended divergence as a defect to fix. Prefers the new element to inherit the existing system (shared tokens, same underlying backdrop) rather than imitate the look with hard-coded values. Confidence: 0.6

- When asked to mirror an existing section/pattern on another page, wants the result "similar but not necessarily identical": reuse the underlying motion/interaction language (e.g. the same looping/scroll technique) while deliberately differentiating the object (row count, framing/containment, fade direction, image framing, pace) so it reads as its own element rather than a copy of the source. Confidence: 0.6
- Prefers media/content bands (marquees, image strips) to run full-bleed edge-to-edge rather than sit inside a contained glass/boxed panel — explicitly asked to "remove the glass container" from the "What it feels like" marquee so it spans the viewport like the landing hero marquee, treating containment (border, gradient, blur, inset shadow) as something to strip rather than preserve. Confidence: 0.5
- Expects shared UI elements (e.g., the header cart icon) to be present and functional on every page — notices when an element shows up on only some pages and asks whether that was "intentional or missed," treating any page where the element is missing or dead as an inconsistency to fix rather than acceptable divergence. Confidence: 0.65
- Expects card/grid sections to adapt to how many items they actually contain: a single item fills the row in a re-laid-out form (e.g. image beside text), two split the row, three sit side by side, and beyond a threshold (four or more) the section becomes a scrollable carousel/rail. A fixed multi-column grid that leaves a lone card stranded in the first of three columns reads as broken. Confidence: 0.7
- Treats the canonical column count as the base structure to retain, not something a fluid `auto-fit`/`minmax` track should collapse — rejects a lone card stretched to the full container width just as much as a lone card stranded in one of three columns. Under-count cases should switch to the same adaptive treatment already used elsewhere (the "Latest stories" band: full-width feature with image beside text) rather than invent a new layout, and the same treatment is expected to hold consistently across every surface that lists the items (blog listing and the home band together). Confidence: 0.65
- Expects every major section to carry a visible heading with the same treatment as its neighbouring sections, rather than a titleless block of cards. Confidence: 0.55
- Wants the content measure of a page's sections aligned to the *inner text* edges of a full-bleed glass panel (where the panel's heading starts and its copy ends), not to the outer glass/box edge — explicitly "match/align with the start of the text ... (not the outer glass-proof container)". Derive both from the same shared tokens so section edges and panel text stay in lockstep. Confidence: 0.6
- Wants author/designer attribution (e.g. the "Site by Edward Rajah" credit) treated as quiet metadata rather than a feature: it must be "subtle and not trying to steal the show/limelight from the owner's site," held at the same size/weight/colour as the copyright line and placed within the existing footer legal row rather than promoted to a prominent standalone element. When unsure, expects the agent to reason about which placement is genuinely less conspicuous and recommend it. Confidence: 0.6
- When a CMS/admin toggle hides a piece of content (e.g. prices), expects the element to be completely removed from the DOM — not rendered with placeholder/fallback text like "Pricing on request". The toggle gates existence, not just the visible string. Confidence: 0.8
- Prefers decorative card numbering removed ("Remove the 01, etc., numberings") and titles to lead the card, keeping numeric prefixes only where the sequence is genuinely part of the meaning (e.g. keeps 01–05 on "What to expect" but drops them from "How it works" and the product/tool cards). Confidence: 0.6
